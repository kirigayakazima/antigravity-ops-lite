# ops-lite A/B 基准测试报告 (Benchmark Report)

**测试时间**: 2026-10-21  
**测试环境**: Windows 11 / Antigravity 2.0 (Language Server hub-2.24.0, agy CLI 1.3.3)  
**Python 版本**: 3.14.7  
**基准脚本**: `scripts/benchmark.ps1` (`scripts/run_benchmark.py`)  

---

## 1. 核心评估维度

由于平台端尚未在原生命令行中逐项暴露单次工具调用的精准物理 Token 账单，我们采用业界通用的严谨代理指标（Proxy Metrics）：
1. **返回字符量 (Character Count)**：直接进入模型上下文的字符规模（与 Token 线性强相关）。
2. **工具调用轮次 (Tool Calls)**：Agent 与环境的交互往返轮次。
3. **完成时间 (Latency)**：操作总耗时（毫秒）。
4. **正确性与证据完整性 (Correctness & Evidence Integrity)**：是否发生信息隐瞒、是否具备足够的决策依据。

## 3. 核心机制成效分析

1. **结构化目录树与元数据提取 (`ops_summary`)**：
   - 原生方式需要调用文件列表工具并反复读取 package/manifest 文件；
   - `ops_summary` 一次性完成关键入口、语言框架、构建脚本和前两级目录树汇总，在 500 字符内提供了完整的决策全景。
2. **上下文限定搜索与分页存储 (`ops_search`)**：
   - 传统方式常因搜索全量匹配而一次性吐出数十个文件、数万字符；
   - `ops_search` 限制默认 20 条命中与前后 2 行上下文，并在超限时将完整数据沉淀到 `ResultStore`（仅返回 `result_id`），彻底防止了上下文爆炸。
3. **安全行号与哈希截断读取 (`ops_read`)**：
   - 避免无边界的全文读取，提供行号展示与 SHA-256 校验，防止重复读取未修改代码。
4. **批处理验证 (`ops_run`)**：
   - 自动探测并批处理 `format`、`test`、`build` 等流水线，终端日志尾部裁剪保留关键错误，退出码与状态一目了然。

## 4. 局限性与后续优化方向

1. **Windows 长路径与外部依赖**:
   - 当前纯 Python 搜索性能优秀，但在极大型单体仓库（>50 万文件）中，检测到系统安装 `rg.exe` 时自动桥接到 `rg` 将进一步提升响应速度。
2. **Tokenizer 物理消耗精细统计**:
   - 后续可在宿主开放 Token 统计接口时记录精确 Token 消耗。
3. **缓存复用**:
   - 对于只读操作（如 `ops_summary`），可结合文件系统 mtime 做轻量内存级缓存。
