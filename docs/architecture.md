# ops-lite 架构设计文档 (Architecture Document)

## 1. 系统分层设计

ops-lite 遵循分层解耦、职责单一的设计原则：

```text
+-------------------------------------------------------------+
|               Antigravity 2.0 Agent Core                    |
|  - 语义理解、架构决策、多轮推理与执行调度                  |
+-------------------------------------------------------------+
                              |
       +----------------------+----------------------+
       |                                             |
+--------------------------+             +--------------------------+
|  Rules (rules/AGENTS.md) |             |  Skills (skills/*/SKILL) |
|  - 脚本优先执行准则       |             |  - 渐进式披露操作工作流  |
+--------------------------+             +--------------------------+
                              |
+-------------------------------------------------------------+
|                 MCP Server (ops-lite)                       |
|  - 标准 Stdio 通信 (JSON-RPC 2.0)                           |
|  - 5 项高能原子工具: ops_summary, ops_search, ops_read,      |
|    ops_run, ops_result                                      |
+-------------------------------------------------------------+
                              |
       +----------------------+----------------------+
       |                                             |
+--------------------------+             +--------------------------+
|  Security & Policy Layer |             | Local Result Store       |
|  - 路径边界隔离          |             | - 离线大结果持久化       |
|  - 敏感凭据正则脱敏      |             | - 安全随机 ID            |
|  - 字符与行数预算硬限制  |             | - 24h 过期与自动滚动淘汰 |
+--------------------------+             +--------------------------+
                              |
+-------------------------------------------------------------+
|             Local Workspaces & Project Files                |
+-------------------------------------------------------------+
```

## 2. 核心组件详解

### 2.1 规则与技能层 (Rules & Skills)
- **`rules/AGENTS.md`**：为模型提供常量级精简的“脚本优先”心智模型，强制要求在进行大范围搜索、文件遍历与流水线验证时优先选用 `ops-lite` 工具。
- **Skills (`repo-inspection`, `efficient-editing`, `verify-changes`)**：采用**渐进式披露 (Progressive Disclosure)**，仅在触发相应任务场景时按需激活，避免常驻系统提示词造成上下文浪费。

### 2.2 工具层 (MCP Server)
1. **`ops_summary`**：解析项目依赖清单（`pyproject.toml`, `package.json`, `Cargo.toml` 等），提取关键入口、配置脚本与 2 级目录树，输出控制在 8,000 字符内。
2. **`ops_search`**：内置多条件正则/字符扫描器，自动排除 `.git`, `node_modules`, `dist` 等构建产物；支持上下文行数提取；超过最大命中数时自动将全量数据暂存至 `ResultStore` 并提供 `result_id`。
3. **`ops_read`**：只读指定行范围（1-indexed），附带行号前缀、文件相对路径与 SHA-256 哈希；自动拒绝二进制文件与设备句柄。
4. **`ops_run`**：拒绝任意 Shell 字符串注入，只接受预定义安全的确定性任务：
   - `verify`：调用项目内置的测试、格式化与构建工具；
   - `git_summary`：提取 Git 增量变更、Diff 统计与安全差异代码段；
   - `inspect`：提取综合概览。
5. **`ops_result`**：用于分页拉取历史大结果，防范单次调用导致上下文溢出。

### 2.3 结果存储引擎 (`results.py`)
- 存放于操作系统临时目录下的专属受限目录；
- 索引采用加密安全的 16 字节随机十六进制 `res_<hex>`；
- 支持 `offset` 与 `limit` 切片，每页限制 20-100 项，读取时再次执行敏感脱敏与最大字符保护；
- 实施 24 小时生命周期与最大 50 条记录自动淘汰机制。
